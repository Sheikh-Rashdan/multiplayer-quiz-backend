# Multiplayer Quiz Backend

A FastAPI backend for a multiplayer quiz application with JWT authentication, quiz/question management, and real-time room gameplay over WebSockets.

Hosted backend: https://multiplayer-quiz-backend.onrender.com/ <br />
Hosted frontend: https://multiplayer-quiz-frontend.onrender.com/

## Overview

This project was built to explore how to model a multiplayer quiz system end-to-end: user accounts, quiz ownership, question sets, room state, and live answer processing in real time. The browser client is the [Multiplayer Quiz Frontend](https://github.com/Sheikh-Rashdan/multiplayer-quiz-frontend), a React and Vite application.

The server exposes a REST API for managing users, quizzes, and questions, and a WebSocket endpoint for live room sessions.

## Features

- JWT-based signup and login flow
- Authenticated user lookup and profile access
- Quiz creation, listing, update, and deletion
- Question creation and editing per quiz
- Quiz ownership checks for protected actions
- Room creation with unique room codes
- Live quiz lifecycle updates over WebSockets
- Host-driven room control and answer validation

## Tech Stack

- Python 3.14+
- FastAPI
- SQLAlchemy
- Pydantic
- PostgreSQL/SQLite support via SQLAlchemy connection strings
- WebSockets for multiplayer room communication

## Quick Start

1. Clone the repository:

```bash
git clone https://github.com/Sheikh-Rashdan/multiplayer-quiz-backend.git
cd multiplayer-quiz-backend
```

2. Create a local environment file from the example:

```bash
cp .env.example .env
```

3. Update the environment variables in `.env`.

Example:

```env
SECRET_KEY=replace_with_a_secure_key
DATABASE_URL=sqlite:///database/questions.db
ALLOW_ORIGIN=http://localhost:5173
```

Notes:

- `DATABASE_URL` can point to SQLite for local development or any SQLAlchemy-supported database.
- `ALLOW_ORIGIN` is optional and is used for CORS during frontend development.

4. Install dependencies:

```bash
uv sync
```

5. Start the backend server:

```bash
uv run uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

The API will be available at:

- Local Swagger UI: http://localhost:8000/docs
- Local ReDoc: http://localhost:8000/redoc
- Hosted backend: https://multiplayer-quiz-backend.onrender.com/

## API Overview

### Authentication

- `POST /users/signup` — create a new user account
- `POST /users/login` — log in and receive a JWT token
- `GET /users/me` — fetch the authenticated user profile
- `GET /users/{user_id}` — fetch a user by ID

### Quizzes

- `GET /quizzes` — list all quizzes
- `GET /quizzes/me` — list the current user's quizzes
- `GET /quizzes/{quiz_id}` — fetch a quiz by ID
- `POST /quizzes` — create a quiz
- `PATCH /quizzes/{quiz_id}` — update a quiz
- `DELETE /quizzes/{quiz_id}` — delete a quiz

### Questions

- `GET /quizzes/{quiz_id}/questions` — list questions for a quiz
- `GET /quizzes/{quiz_id}/questions/{question_id}` — get a question by ID
- `POST /quizzes/{quiz_id}/questions` — create a question
- `PATCH /quizzes/{quiz_id}/questions/{question_id}` — update a question
- `DELETE /quizzes/{quiz_id}/questions/{question_id}` — delete a question

### Rooms

- `POST /rooms` — create a room for a quiz
- `GET /rooms/{room_id}` — fetch room details
- `WS /rooms/{room_id}` — connect to a live room WebSocket

## Frontend Integration

The [hosted frontend](https://multiplayer-quiz-frontend.onrender.com/) uses this backend for authentication, quiz and question management, and live room gameplay. Configure the frontend's `VITE_API_URL` to this backend's base URL:

```env
VITE_API_URL=https://multiplayer-quiz-backend.onrender.com
```

For local frontend development, use `http://127.0.0.1:8000` and set `ALLOW_ORIGIN=http://localhost:5173` in the backend's `.env`. The backend allows `http://localhost:5173` by default; `ALLOW_ORIGIN` adds the configured frontend origin for cross-origin REST requests.

The frontend opens the room WebSocket at `/rooms/{room_id}` and supplies its JWT as the `token` query parameter. It uses the authentication, quiz, question, and room routes listed above. The interactive API documentation is available at [the hosted Swagger UI](https://multiplayer-quiz-backend.onrender.com/docs).

## WebSocket Gameplay

The WebSocket endpoint is used to coordinate multiplayer quiz sessions in real time.

Typical flow:

1. A quiz owner creates a room.
2. Players join the room through the room code / room ID.
3. The host starts the quiz session.
4. Participants submit answers over the live connection.
5. Server validates answers and pushes updated room state back to clients.

## Notes and Constraints

- Only the quiz author can update or delete their own quiz.
- Only a quiz owner can create rooms from that quiz.
- Database tables are created automatically on startup via the app's lifespan handler.
- This project is intended as a learning-focused implementation for building real-time quiz infrastructure with FastAPI.
